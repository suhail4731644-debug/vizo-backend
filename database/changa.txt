 1.2  EVERYBODY SIGNS OUT AND BACK IN — the same day

      Permissions travel INSIDE the JWT, as "perm" claims, and a token lasts
      eight hours (Jwt:ExpiryMinutes = 480). A salesperson holding a token
      issued before the migration still carries the old five permissions, and
      will go on being refused the invoice screen until it expires.

      Signing out and back in fixes it immediately. Doing nothing fixes it by
      tomorrow morning. There is no server-side way to force it short of
      rotating Jwt:Key, which would sign everybody out including you.


 1.3  SET THE WEBSITE ADDRESS ON THE API HOST

      New setting, because every notification now carries a real link instead
      of a bare path like "/sales/orders/42":

          App__WebBaseUrl = https://advpos-frontend.vercel.app

      Set it as an ENVIRONMENT VARIABLE wherever the API runs (Railway →
      Variables). The double underscore is ASP.NET's own convention for
      nesting; it overrides the value committed in appsettings.json, which is
      already set to the same thing as a fallback.

      Change this one line and every notification, every push and every link in
      the bell follows it. That was the point of asking for it.

      WHY IT MATTERS: a Web Push payload is opened by the service worker with
      clients.openWindow(). A bare path there resolves against the worker's own
      scope rather than against your site — it happens to work while the app is
      the only thing on that origin and stops working the day it is not. And
      when somebody forwards a notification to a colleague, a path is not a
      link at all.

      In-app it still behaves as it always did: the bell turns a link back into
      a path when it points at the site you are already on, so clicking one
      does not reload the whole application.


 1.4  ADD THE VERCEL ORIGIN TO CORS — probably already done, check anyway

          "Cors": { "AllowedOrigins": [ ..., "https://advpos-frontend.vercel.app" ] }
